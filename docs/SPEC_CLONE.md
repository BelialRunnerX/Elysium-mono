# Clone plan: Apotheosis and Silent Gear, rebuilt as Elysium

The build order for replacing the mechanics of Apotheosis and Silent Gear with Elysium's own. Work down it the way `SPEC_FEATURES.md` is worked: one row at a time, architect, implement, validate, then the next.

## Sources

Every row traces to a feature in one of two reference inventories, each built from the mods' own jars — their data files, language files, in-game manuals and bytecode — with the web used only to fill gaps, and every web-sourced or inferred number marked as such in the inventory:

| Reference | Covers | Versions (the "Elysium Mod test" instance) |
|---|---|---|
| [`reference/apotheosis_inventory.md`](reference/apotheosis_inventory.md) | 70 features: AA, AP, AE, AS, PL | Apotheosis 8.8.0, Apothic Attributes 2.10.1, Apothic Enchanting 1.6.2, Apothic Spawners 1.4.0, Placebo 9.9.2 |
| [`reference/silentgear_inventory.md`](reference/silentgear_inventory.md) | 77 features: SG | Silent Gear 4.2.1.1, Silent Lib 10.6.0 |

The inventory has the exact numbers, formulas, file paths and content lists (all 94 affixes, 23 gems, 132 materials, 48 parts, 75 traits, the enchantments and shelves). This file has the order. Spot-checked against the jars: rarity rule lists, reforge costs (2/5/15/30/50 levels), the 94/23 affix and gem counts, the 132/48/75 Silent Gear counts, and the grade bonuses (E +1% … MAX +30%) all match.

**Scope:** 147 features. Elysium today has 4 of them, 58 in part, and 85 not at all. Sizes: 60 S, 65 M, 17 L, 5 XL.

## Rulings the clone must follow

These are owner decisions that already stand, and they change how some features are cloned:

1. **No caps. Every percentage is stat / (stat + b).** Where an original caps a number, the clone does not. Where the number is a percentage — a chance, or a share of something removed — it is derived from an uncapped stat through `ElysiumShares` instead of being clamped. The originals' caps, and what each becomes:

   | Original | Cap in the original | In the clone |
   |---|---|---|
   | AA-2 Protection | 2.5% per point, capped at 85% | Protection points are a stat; the share is stat / (stat + b) |
   | AA-5 Life steal, overheal | overheal absorption capped at 50% of max health | Absorption from overheal follows stat / (stat + b) of max health |
   | AP-6/AP-17/AP-18 Affix level | 1.0 standard, 2.0 with Malice/Supremacy | Affix level is uncapped; affixes that grant a percentage convert level to share |
   | AE-1/AE-2 Eterna, Quanta, Arcana; power | clamped 0–100; power 1–200 | **Decision needed** — these are table inputs, not player stats (see below) |
   | AE-9 Forced level cap | per-enchantment | Not cloned |
   | SG-1/SG-2 Property clamps | each property clamped to [min, max] | Clamps removed; percentage properties go through stat / (stat + b) |
   | SG-15 Synergy | clamped to 0.1–2.0 | Synergy uncapped above; a floor stays only where a negative value would invert a stat |
   | SG-14 Grade | tops out at MAX (+30%) | **Decision needed** — grades are a named ladder, not a number |

   Kept, because they are physics or arithmetic rather than balance: arrow velocity's cap of 1 (SG-37), the 1000-block tree-felling limit (SG-34), vanilla's 255 effect-level byte, and anything guarding against a negative that would invert a stat.
2. **The GUI is signed off.** Existing screens do not change. The many new stations here (salvaging, reforging, gem cutting, augmenting, alloy forge, grader, starlight charger, enchanting) need new screens, built in the existing `ElysiumUI` style.
3. **`elysium-solarpunk` depends on nothing.** Nothing here is placed in it.
4. **Every row ends with a validator rule and a negative test,** the way the rest of the mod is built.

## Decisions needed before the phase that needs them

| Before | Decision | The choice |
|---|---|---|
| P3 | **Modular gear vs fixed-shape gear.** | Silent Gear builds every tool from parts of several materials; Elysium builds nine fixed shapes of one material. Replace the fixed shapes with modular ones, or keep both (fixed shapes as the early, simple path)? |
| P4 | **One effect engine.** | Recommended: Silent Gear traits, Apotheosis affixes, gems and Elysium runes all become one system of conditional item effects, rather than four. |
| P5 | **World tiers vs standing.** | Apotheosis gates everything by five player-chosen World Tiers. Elysium already has Favor/Suspicion bands and clearance tiers. Adopt World Tiers, map them onto standing, or both? |
| P7 | **Gems vs runes.** | Apotheosis gems (purity, gem classes, per-item-type bonuses) and Elysium runes (elements, alignment, tiers by merging) overlap. Merge into one socketable, or keep both? |
| P8 | **Grades vs maker's marks.** | Silent Gear grades (catalyst roll at a machine) and Elysium quality grades (earned by crafter practice) overlap. Keep both, or fold one into the other? |
| P10 | **Enchanting table caps.** | Eterna/Quanta/Arcana are the table's inputs, and power 1–200 bounds the enchantment roll. Uncap them, or treat them as the table's physics? |
| end | **The compat bridges.** | Elysium has an Apotheosis bridge and Silent Gear materials data. Once a system is cloned, remove the bridge, or keep it so both can be installed together? |

### P4 · One item-effect engine

Silent Gear traits and Apotheosis affixes are the same idea — conditional effects attached to an item. Built once, shared by traits, affixes, gems and runes.

Built, and built once: `ElysiumEffectKinds` names the twenty kinds an effect can be, `ElysiumItemEffects` gathers them from every attachment a stack has, and `ElysiumEffectHandlers` acts on them. A bleed from an affix is the same bleed as a bleed from a trait, down to the duration, because it is the same code reading the same words. Traits register as one attachment and affixes as another; gems and runes join the same way when their phases arrive.

|---|---|---|---|---|---|
| P4.1 | AP-4 | Loot categories (what kind of gear an item is) | PARTIAL — `ElysiumGear` decides "is gear" via `TieredItem`, armour slot or attack-damage modifier, but it has no category taxonomy | S | DONE — the taxonomy is `ElysiumGearTree` in the library: 44 kinds in a tree, each a sort of its parent, so a rule written for `melee_weapon` catches a katana and one written for `pickaxe` catches a hammer. `ElysiumLootCategory` answers what kind a stack is by asking the item first (anything implementing `ElysiumKinded`, which modular gear must, since a sword and a pickaxe are the same class), then its vanilla class, then what it does. `ArmoryGearType` reads its rows from the same tree rather than keeping a second copy. |
